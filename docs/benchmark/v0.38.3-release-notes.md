# v0.38.3 remove failed batching requirement

Status: evidence-based hot-path deletion. This release does not claim included-plan allowance superiority.

## Change

Remove the v0.38.1 instruction that required Sol to acquire the Skill, task contract, dependencies, acceptance inputs, and test list in one bounded action. The launch-ready capsule, exact workdir and executable, single retained Luna, one completion wait, and one final-suite executor remain unchanged.

## Why

P122 showed a cheaper isolated controller prefix, but the frozen equal-quality P118 full route did not transfer that gain. The batched v0.38.2 route cost `4.913135` credit equivalent and took `185.211` seconds. The earlier v0.38.0 route on the same task cost `4.678860` and took `155.579` seconds. Both passed 24 public and 8 hidden checks with no repair or Sol rewrite.

This is a deletion, not a new optimization claim. One matched task cannot prove universal causality, but a normal-path requirement with no full-route benefit does not earn a permanent place in the Skill.

## Release-history gate repair

The first guarded preview exposed that repeat detection considered the original mechanism families but not mechanisms introduced by later release entries. The publisher now includes every earlier release entry in the mechanism history and requires the candidate entry to be last. This repair runs only during release; it adds no ordinary Sol–Luna action or context.

## Boundaries

- Keep v0.37.9's single completion wait and v0.38.0's evidence-bound effort rule.
- Do not retry batching by changing command grouping or wording. A retry requires a host or protocol change that reduces complete-route cost without removing capsule semantics.
- Diagnostic credit equivalents are not five-hour or weekly included-plan percentages.
- `v0.1.1` remains GitHub Latest.
