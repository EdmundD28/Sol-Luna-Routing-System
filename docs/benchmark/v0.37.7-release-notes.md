# v0.37.7 delegated-authority recognition

Status: experimental ordinary release. It does not establish included-plan allowance savings.

## Problem and changed premise

The v0.37.6 worker contract said to continue only after required user confirmation. In a disposable preparation-directory probe, a fresh `luna_worker_low` treated that wording as authority to invent another confirmation gate even though the user had authorized autonomous continuation and the parent package explicitly authorized the exact reversible edit. This differs from the earlier edit-safety work: the failure was not a host refusal that should be bypassed, but a false refusal created by the contract itself.

## Change

The Skill and six writer profiles now state that a user-authorized bounded parent package permits its edits. Missing authority and actual tool or host refusals still return `BLOCK`; sandbox, ownership, acceptance, network, publication, and destructive-action limits are unchanged. The Skill is 1194 words and each writer profile is 184 words, both within the existing limits.

## Evidence and limit

- Old contract: the explicitly authorized disposable probe was refused.
- Candidate contract: a fresh `gpt-5.6-luna` at Low created the exact 18-byte file on the first attempt; the file was verified and removed.
- Contract tests: 15/15 passed before the final release gate.
- Independent read-only review: `REVIEW_PASS` for safety, history distinction, and regression coverage.

This is mechanism evidence only. It does not replace a matched five-hour and weekly allowance comparison, and it does not justify a general allowance-saving claim.
