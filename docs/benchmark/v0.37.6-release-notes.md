# v0.37.6 release notes

This bounded correction requires ordinary dispatches to carry launch-ready acceptance capsules. Each capsule states the canonical repository workdir, exact executable and arguments, and environment values already resolved from that workdir. It is an auditable instruction contract, not runtime enforcement. A capsule defect found before launch returns `BLOCK` with `K=ACCEPTANCE_CAPSULE`; an exact launch failure before test collection returns infrastructure `FAILED`. Neither is quality evidence or justifies effort escalation; retry requires a corrected capsule rather than an implementation repair.

The changed premise is host-observed. P103 launched with `PYTHONPATH=benchmarks\\p087_fixture` from the repository root and collected zero of 59 intended tests because five public modules failed to import; the corrected absolute-root diagnostic collected 59 tests and still found 18 failures and 16 errors. P104 supplied two relative `PYTHONPATH` entries but launched from the fixture tests directory, so `opsworkbench` failed to import; the corrected absolute-root diagnostic collected 56 tests and still found 8 failures and 7 errors. Both candidates were restored. These routes did not pass, no quota reading was taken, and the evidence supports only delivery correctness.
