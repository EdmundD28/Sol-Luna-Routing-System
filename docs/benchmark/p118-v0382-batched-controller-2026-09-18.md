# P118 v0.38.2 batched-controller full-route ablation

Status: equal-quality full-route rejection of the controller-only economic hypothesis. This is a same-task development-set result, not an included-plan allowance claim.

## Frozen comparison

The candidate reused P118's baseline, task, public suite, hidden referee, ownership, one Luna Medium writer, repair limit, absolute interpreter, workdir, and Sol-only reference. The only changed mechanism was acquiring the installed Skill, task specification, complete public test body, and test listing in one Sol action. The freeze received independent review before the candidate branch existed.

| Measure | Frozen Sol-only | v0.38.2 batched Sol-Luna | Result |
|---|---:|---:|---|
| Public acceptance | 24/24 | 24/24 | equal |
| Hidden acceptance | 8/8 | 8/8 | equal |
| Repair / Sol rewrite | 0 / n/a | 0 / 0 | pass |
| Credit equivalent | 8.395480 | 4.913135 | -41.478808%; misses 50% gate |
| Wall time | 155.633 s | 185.211 s | +19.004967%; fails time gate |

The candidate controller made exactly one frozen read, one Medium-writer spawn, and one long wait. It did not implement, reread, retest, repair, poll, enumerate agents, rewrite, or reclaim. The writer ran the public suite once and passed; route-external hidden acceptance also passed. Independent result review reproduced the host counters, model identities, sequence, arithmetic, and failure decision.

## Attribution

Complete fresh-session counters produced `4.492800` for the Sol controller and `0.420335` for the Luna writer. Total `4.913135` is `5.007096%` more expensive than the earlier v0.38.0 P118 Sol-Luna route, and `185.211` seconds is `19.046272%` slower. Nearly identical writer launch-message sizes rule out an intentionally shortened or incomplete capsule as the explanation.

## Decision

The P122 controller-only microbenchmark showed that batching can reduce an isolated acquisition prefix, but P118 shows that this saving does not survive a complete implementation route. Because the rule is ordinary-path work with no demonstrated route benefit, v0.38.3 removes it rather than preserving a failed micro-optimization.

Close this direction under the current premise. A retry requires a host or protocol change that measurably reduces the complete launch capsule or controller output without removing task semantics, acceptance detail, exact executable/workdir, or quality. Rebatching the same inputs is not a changed premise.

## Limits

- The result rejects this mechanism on one matched development task; it does not prove batching is always harmful.
- Diagnostic purchased-credit equivalents are not five-hour or weekly included-plan percentages.
- Host and cache variance remain possible, so the result supports stopping further investment rather than a universal causal estimate.
