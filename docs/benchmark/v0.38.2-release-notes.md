# v0.38.2 implicit discovery alignment

Status: installation metadata correction. It does not change routing, worker behavior, task quality, proxy credit, or elapsed-time claims.

## Problem

The verified desktop installation exposes `$sol-luna` with `policy.allow_implicit_invocation: true`, but the repository still packaged `false`. A managed update from v0.38.1 therefore treated `agents/openai.yaml` as a conflict and, if forcibly replaced outside the lifecycle guard, would disable the discovery behavior the installation currently relies on.

## Change

The packaged metadata now keeps implicit invocation enabled. A package-contract test binds that value so a later release cannot silently turn discovery off. No Skill instruction, agent profile, runtime tool, or ordinary dispatch action is added.

## Evidence and limits

- The current Codex session lists and successfully loads the installed `sol-luna` Skill with the enabled value.
- The v0.38.1 setup preview reported the source-disabled metadata as a conflict and performed no writes.
- This release only removes that source/install mismatch. It does not prove Sol-Luna allowance or time superiority.
